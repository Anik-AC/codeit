# 0005. jira_client implementation details

- **Status:** Accepted
- **Date:** 2026-09-25

## Context

PRD 7.2 and 7.3 describe `jira_client` and the doctor and discover commands. Building M1 needed several decisions the PRD leaves open.

## Decision

**ADF conversion uses markdown-it-py** (CommonMark, raw HTML off), not a hand-written parser.
- Soft line breaks become spaces, as CommonMark specifies. A hard break (`\` at line end) becomes an ADF `hardBreak`.
- Markdown outside CommonMark, such as tables and strikethrough, stays literal text.
- ADF forbids some nesting. A heading inside a list or quote becomes a bold paragraph, a nested quote is flattened, and a rule there is dropped.
- When writing markdown, special characters are escaped so text survives a round trip. Intraword underscores (`snake_case`) are left alone, so code names stay readable for agents.

**Retries never duplicate writes.**
- 429 and 503 are retried for every method, since Jira did not process the request.
- 500, 502, 504 and dropped connections are retried only for idempotent requests. Search is a POST but is marked idempotent.
- Connection failures before sending are always retried.
- A `Retry-After` over 120 seconds raises `JiraRateLimited` with the delay, so the caller can park instead of blocking.

**403 maps to `JiraAuthError`**, like 401. The PRD's four error types are kept. `JiraBadRequest` (400) and `JiraConfigError` (missing `.env` values) are added.

**`config/jira_ids.yaml` is gitignored.** It is specific to one Jira site and regenerated by `codeit jira discover`, and the repo is public. It also stores a `transitions` map (target status name to transition ID), sampled from the newest Story. `transitions.py` seeds its cache from it and refetches on a miss or a stale ID.

**Fields are resolved by name, preferring project scope.** Team-managed projects scope custom fields to one project, so a field scoped to this project beats a global field with the same name. Two candidates at the same level are reported as ambiguous. Story points match either "Story point estimate" (team-managed) or "Story Points".

**Statuses and transitions come from the Story workflow only.** CodeIt moves only Stories through the lifecycle (PRD 6.1). Epics, Tasks and Subtasks may keep Jira's default workflow, as they do on the owner's site. Discovery reads statuses for the Story work type, and discover and doctor sample the newest Story for transitions.

**Doctor checks more than PRD 7.3 lists:**
- the Epic and Story work types exist
- each custom field is on the Story work type, not just on the site
- every required status can be reached from a sample issue, which checks the "allow all" setting from PRD 7.1

It lives in `doctor.py`.

**Issue link direction** (`inwardIssue` = the blocker) is checked against the live site by `test_link_direction`. If Jira behaves otherwise, the fix is one function, `issues.link_issues`.

## Consequences

- New runtime dependency: `markdown-it-py`.
- The first `LIVE=1` run (2026-09-25) passed all 6 live tests. That confirms Jira accepts the ADF, the link direction, transitions to every status, custom field writes and token paging. It also exposed that sampling any work type picked a Subtask on the default workflow, which led to the Story-only rule above.
